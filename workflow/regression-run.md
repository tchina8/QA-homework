# Workflow: регрессионный прогон кредитного калькулятора

Процедура. Запускается целиком, повторяемая, с разделением ролей: **тот, кто
прогоняет, не проверяет собственный результат**.

Скопируйте текст ниже в сессию агента как задание либо выполните шаги руками —
детерминированная часть в любом случае делается одним и тем же скриптом,
поэтому результат не зависит от того, что модель себе придумает.

---

## Роли

| Роль | Кто | Что делает |
|---|---|---|
| **Исполнитель** | субагент A | шаги 1–5: прогон, разбор, сравнение, проверка findings, сборка отчёта |
| **Проверяющий** | субагент B, **другой** | шаг 6: независимая сверка и финальная строка |

Проверяющий не участвует в прогоне и не видит выводов исполнителя, кроме
файлов-артефактов. Смысл разделения тот же, что и в задании: автор не бывает
независимым проверяющим собственной работы.

---

## Задание исполнителю (субагент A)

```
Ты выполняешь шаги 1–5 регрессионного прогона кредитного калькулятора.
Работаешь в корне репозитория. Интерпретатор — только из .venv по прямому пути.

Выполни последовательно, каждую команду отдельно, и покажи вывод каждой:

  .venv\Scripts\python.exe workflow\run_regression.py step1
  .venv\Scripts\python.exe workflow\run_regression.py step2 --stamp <STAMP>
  .venv\Scripts\python.exe workflow\run_regression.py step3 --stamp <STAMP>
  .venv\Scripts\python.exe workflow\run_regression.py step4 --stamp <STAMP>
  .venv\Scripts\python.exe workflow\run_regression.py step5 --stamp <STAMP>

<STAMP> печатает шаг 1 последней строкой в виде STAMP=ГГГГ-ММ-ДД_ЧЧММСС.
Подставь его во все последующие шаги без изменений.

Правила:
— ничего не чини и не правь: ни тесты, ни calc/, ни findings.md.
  Твоя работа — прогнать и собрать факты, а не улучшать результат;
— если шаг упал, не обходи его и не пропускай: покажи ошибку и остановись;
— не делай выводов о качестве регресса, не пиши вердикт и не трогай
  раздел «Вердикт» в отчёте — это работа другого агента.

В конце сообщи: STAMP, путь к отчёту и итоговые числа из шага 2.
```

## Задание проверяющему (субагент B)

```
Ты проверяешь результат регрессионного прогона, который выполнял ДРУГОЙ агент.
Ты его работу не видел и на слово ему не веришь.

Тебе дан STAMP=<STAMP>. Работаешь в корне репозитория, интерпретатор —
только из .venv по прямому пути.

1. Убедись, что все шесть артефактов на месте:
     reports/raw/<STAMP>.txt
     reports/steps/<STAMP>-01-run.json
     reports/steps/<STAMP>-02-parsed.json
     reports/steps/<STAMP>-03-compare.json
     reports/steps/<STAMP>-04-findings.json
     reports/steps/<STAMP>-05-report.json
     reports/report-<STAMP>.md
   Отсутствие любого — шаг workflow не выполнен, так и напиши.

2. Пересчитай итоги САМ, из сырого вывода reports/raw/<STAMP>.txt,
   не доверяя разбору шага 2. Сравни свои числа с -02-parsed.json.
   Расхождение — дефект workflow, а не мелочь.

3. Проверь по -03-compare.json: не появился ли XPASS, не сломалось ли то,
   что раньше проходило. XPASS означает, что дефект починили, не сняв
   пометку xfail, — это всегда требует внимания.

4. Проверь по -04-findings.json: у каждого ОТКРЫТОГО бага из findings.md
   должен быть живой тест. Открытый баг без теста — дыра: при следующей
   правке кода он не подаст сигнала. Сверься с самим findings.md, а не
   только с json.

5. Проверь, что число тестов не уменьшилось по сравнению с предыдущим
   прогоном без объяснения. Исчезнувший тест — самый тихий способ
   сделать прогон зелёным.

Запиши результат в reports/steps/<STAMP>-06-verdict.md и тем же текстом
замени раздел «Вердикт» в reports/report-<STAMP>.md.

Формат вердикта — ровно три строки, каждая начинается с указанного слова:

  СДЕЛАНО: <что прогон подтвердил>
  НЕ ПОЛУЧИЛОСЬ: <что не сработало или осталось недоказанным; если всё
                  сработало — так и напиши, но проверь дважды>
  ОСТАЛОСЬ: <что требует решения человека>

Правила:
— ничего не чини: ни тесты, ни calc/, ни findings.md;
— зелёный прогон сам по себе не является доказательством качества.
  Если покрытие имеет известные слепые зоны, скажи это в строке
  НЕ ПОЛУЧИЛОСЬ, даже когда все тесты прошли.
```

## Артефакты: чем доказывается, что шаг выполнен

| Шаг | Файл | Что доказывает |
|---|---|---|
| 1 | `reports/raw/<STAMP>.txt` | прогон состоялся, вывод сохранён целиком |
| 1 | `reports/steps/<STAMP>-01-run.json` | команда, код возврата, длительность |
| 2 | `reports/steps/<STAMP>-02-parsed.json` | итоги и разбивка по трём файлам |
| 3 | `reports/steps/<STAMP>-03-compare.json` | что починилось, что сломалось, XPASS |
| 4 | `reports/steps/<STAMP>-04-findings.json` | у каких багов есть живой тест |
| 5 | `reports/report-<STAMP>.md` | собранный отчёт |
| 6 | `reports/steps/<STAMP>-06-verdict.md` | вердикт проверяющего, три строки |

Отсутствие файла означает, что шаг не выполнялся. Это и есть проверка
исполнения: не «агент сказал, что сделал», а «файл лежит».
