# Спецификация кредитного калькулятора

Источник истины для всех тестов регресса. ДЗ №2, вариант **B4** — регресс кредитного
калькулятора: ставка, срок, досрочное погашение, страховка.

Все числа в разделе «Эталонные примеры» получены расчётом (Python 3.13.15, `Decimal`,
`.venv\Scripts\python.exe`), а не выписаны по памяти. Если тест расходится с этим
документом — неправ тест или код, но не документ; расхождение чинится изменением спеки
через отдельный коммит.

## 1. Область применения и принятые решения

Решения приняты до написания спеки и обсуждению не подлежат. Здесь они зафиксированы,
чтобы тест мог на них ссылаться.

| Решение | Формулировка |
|---|---|
| Тип денег | `Decimal`, создаётся **только из строк**. `Decimal(float)` запрещён на любом пути. |
| Округление | `ROUND_HALF_UP` до 2 знаков. Реализовано **единственной функцией** в `calc/money.py`. |
| Что округляется | Результат каждого платежа и его процентная часть. Промежуточные множители — **нет**. |
| База начисления | 30/360. Все месяцы равны, `i = годовая ставка / 12`. |
| Схема погашения | Аннуитет. |
| Страховка | Две схемы: единовременная из своих средств, единовременная в кредит. |
| Досрочное погашение | Два вида: сокращение срока, уменьшение платежа. |

Вне области: фактические дни, ACT/365, високосный год, ежегодная и ежемесячная страховка,
скидка к ставке за страховку, дифференцированные платежи. Подробно — в разделе 8.

### 1.1. Контракт округления

`calc/money.py` содержит ровно одну публичную функцию округления. Ни один другой модуль
не вызывает `quantize`, не импортирует `ROUND_*` и не округляет самостоятельно.

```python
def money(x: Decimal) -> Decimal:
    """Единственная точка округления: ROUND_HALF_UP до 2 знаков."""
    return x.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
```

Проверяется тестом-стражем: `grep` по `calc/` не должен находить `quantize` или
`ROUND_HALF_UP` вне `money.py`, и не должен находить `Decimal(` с аргументом-float.

## 2. Обозначения

| Символ | Смысл | Тип |
|---|---|---|
| `S` | Тело кредита (сумма к выдаче, после учёта страховки в кредит) | `Decimal`, 2 знака |
| `S_req` | Запрошенная заёмщиком сумма (до страховки) | `Decimal`, 2 знака |
| `r` | Годовая номинальная ставка, доля единицы (12 % → `Decimal("0.12")`); предусловие `r ≥ 0` | `Decimal` |
| `i` | Месячная ставка, `i = r / 12` | `Decimal`, **не округляется** |
| `n` | Срок в месяцах, целое ≥ 1 | `int` |
| `A` | Аннуитетный платёж | `Decimal`, 2 знака |
| `k` | Номер платёжного месяца, `1 … n` | `int` |
| `B_k` | Остаток основного долга **после** платежа `k`; `B_0 = S` | `Decimal`, 2 знака |
| `I_k` | Процентная часть платежа `k` | `Decimal`, 2 знака |
| `D_k` | Основная часть платежа `k` (тело) | `Decimal`, 2 знака |
| `E_k` | Досрочное погашение, внесённое вместе с платежом `k` | `Decimal`, 2 знака |
| `p` | Страховая премия | `Decimal`, 2 знака |
| `ρ` | Тариф страхования, доля от `S_req` | `Decimal` |

## 3. Формулы

### 3.1. Месячная ставка

```
i = r / 12
```

`i` — точное `Decimal`-частное, к 2 знакам **не приводится**. При `r = 12 %`
получается `i = 0.01` ровно; при `r = 9.5 %` — `0.0079166…`, и именно это значение
идёт в формулу.

### 3.2. Аннуитетный платёж

При `i > 0`:

```
            i · (1 + i)^n
A = money( S · ───────────────── )
             (1 + i)^n − 1
```

При `i = 0` формула вырождается (деление на ноль), поэтому определяется отдельно:

```
A = money( S / n )
```

`(1 + i)^n` вычисляется без округления и в промежуточном виде не квантуется.

### 3.3. Разложение платежа `k`

```
I_k = money( B_{k−1} · i )
D_k = A − I_k
B_k = B_{k−1} − D_k − E_k
```

`D_k` дополнительного округления не требует: `A` и `I_k` уже приведены к 2 знакам,
их разность точна.

### 3.4. Балансирующий последний платёж

Из-за округления `A` до копеек накопленная сумма тел не сходится с `S` точно.
Последний платёж **обязан** закрывать остаток полностью. Платёж `k` считается
последним, если выполнено **любое** из двух условий:

```
(а)  A − I_k ≥ B_{k−1}          — платёж уже перекрывает остаток
(б)  k = n                       — исчерпан срок (при схеме «уменьшение платежа» срок фиксирован)
```

Тогда:

```
A_k = money( B_{k−1} + I_k )
D_k = B_{k−1}
B_k = 0
```

> **Почему условие (б) необходимо.** При проверке эталонного примера 2b с одним лишь
> условием (а) график не закрылся: после 12-го платежа оставался хвост `0.01`
> и появлялся фиктивный 13-й платёж на одну копейку. Условие (б) — не украшение,
> а обязательная часть алгоритма. Тест на это обязателен.

### 3.5. Страховка

Премия считается от **запрошенной** суммы, не от тела кредита — это устраняет
круговую зависимость:

```
p = money( S_req · ρ )
```

| Схема | Тело кредита | Денежный поток заёмщика |
|---|---|---|
| Единовременная из своих средств | `S = S_req` | `p` платится отдельно, вне графика; полная нагрузка = сумма платежей + `p` |
| Единовременная в кредит | `S = S_req + p` | `p` внутри графика; на премию **начисляются проценты** |

### 3.6. Досрочное погашение

`E_k` вносится **вместе** с очередным платежом `k` и списывается **после** разнесения
этого платежа на проценты и тело — то есть уменьшает `B_k`, а не `B_{k−1}`. Проценты
месяца `k` начисляются на остаток до досрочки.

`E_k` ограничивается сверху остатком: `E_k_факт = min(E_k, B_k_до_досрочки)`.

| Вид | Что фиксируется | Что пересчитывается |
|---|---|---|
| **Сокращение срока** | Платёж `A` неизменен | Число оставшихся месяцев; график идёт до закрытия по правилу 3.4(а) |
| **Уменьшение платежа** | Срок `n` неизменен | `A' = money(annuity(B_k, i, n − k))`, действует с месяца `k+1` |

## 4. Инварианты

Обязательны **всегда**, в любом сценарии, включая вырожденные. Каждый — отдельный тест,
применяемый ко всем эталонным примерам и к генерируемым кейсам.

| № | Инвариант | Формально |
|---|---|---|
| И-1 | Сумма тел равна телу кредита | `Σ (D_k + E_k) = S`, точное равенство `Decimal` |
| И-2 | Остаток после последнего платежа строго ноль | `B_last == Decimal("0.00")`, сравнение точное, без допуска |
| И-3 | Последний платёж балансирующий | `A_last = money(B_{last−1} + I_last)`, и он **единственный**, который вправе отличаться от `A`. **Исключение:** график, закрытый самой досрочкой, — см. 4.4 |
| И-4 | Проценты **не возрастают** | `I_k ≥ I_{k+1}` для всех `k`. Неравенство **нестрогое**: см. 4.1. При `i = 0` — все `I_k = 0` |
| И-5 | Остаток монотонно убывает | `B_k < B_{k−1}` для всех `k` |
| И-6 | Платёж покрывает проценты | `A_k > I_k`, то есть `D_k > 0`, для всех `k` |
| И-7 | Все величины неотрицательны | `A_k, I_k, D_k, E_k, B_k ≥ 0` |
| И-8 | Ровно 2 знака | `-x.as_tuple().exponent == 2` для каждой денежной величины в графике |
| И-9 | Сумма выплат сходится | `Σ A_k + Σ E_k = S + Σ I_k` |
| И-10 | График конечен, срок не растёт | Число строк ≤ `n`. При досрочке срок сокращается **на 0 или больше** месяцев; строгое `< n` **не гарантировано**: см. 4.2 |

И-3 стоит подчеркнуть отдельно: **ровно одна** строка графика может иметь платёж,
отличный от `A` (при отсутствии досрочек с уменьшением платежа). Тест, который допускает
две такие строки, пропустит дефект округления.

### 4.1. Почему И-4 нестрогое — обязательный тест-кейс

Остаток убывает строго (И-5), но проценты берутся от него **после округления** до копеек.
Если `D_k · i` меньше половины копейки, соседние `I_k` и `I_{k+1}` совпадут.

Подтверждено расчётом. `S = 100.00`, ставка `0.1 %`, `n = 12`, `A = 8.34`:

| k | Платёж | Проценты | Тело | Остаток |
|---:|---:|---:|---:|---:|
| 1 | 8.34 | **0.01** | 8.33 | 91.67 |
| 2 | 8.34 | **0.01** | 8.33 | 83.34 |
| 3 | 8.34 | 0.01 | 8.33 | 75.01 |
| 4 | 8.34 | 0.01 | 8.33 | 66.68 |
| 5 | 8.34 | 0.01 | 8.33 | 58.35 |
| 6 | 8.34 | 0.00 | 8.34 | 50.01 |
| … | 8.34 | 0.00 | 8.34 | … |
| 12 | 8.31 | 0.00 | 8.31 | 0.00 |

Проценты `0.01` держатся пять месяцев подряд, затем падают до `0.00`.
Строгое убывание — `False`, неубывание — `True`. Проценты за весь срок: `0.05`.

Это **не** вырожденный «нулевой» случай: значения ненулевые, кредит нормально
амортизируется, закрывается за 12 месяцев с остатком `0.00`.

> **Обязательный тест-кейс.** Проверять `I_k ≥ I_{k+1}`. Тест на строгое `>` упадёт
> на этих данных ложно. Кейс включается в регресс именно в таком виде.

### 4.2. Почему И-10 не гарантирует сокращение срока — обязательный тест-кейс

Последний платёж и без досрочки меньше регулярного — у него есть запас. Пока досрочка
меньше этого запаса плюс тела последнего платежа, срок не меняется: досрочка уходит
в уменьшение финальной суммы, а не в удаление строки.

Подтверждено расчётом на кредите примера 1 (`1 000 000.00 / 12 % / 12 мес`,
запас последнего платежа `88 848.79 − 88 848.76 = 0.03`), досрочка вносится с платежом №3:

| Досрочка `E_3` | Месяцев | Последний платёж | Экономия процентов |
|---:|---:|---:|---:|
| — | 12 | 88 848.76 | — |
| 0.01 | **12** | 88 848.75 | **0.00** |
| 1.00 | **12** | 88 847.67 | **0.09** |
| 81 237.96 | **12** | **0.01** | 7 610.79 |
| 81 237.97 | **11** | 88 848.78 | 7 610.80 |
| 100 000.00 | 11 | 68 532.20 | 9 165.35 |

Экономия ноль ровно там, где досрочка целиком уходит в запас последнего платежа:
при `0.01` проценты не меняются вовсе (`66 185.45` в обоих случаях). Уже при `1.00`
экономия появляется — `0.09` — хотя срок по-прежнему 12 месяцев. Нулевое сокращение
срока и нулевая экономия процентов — **разные** условия, и совпадают они только
на самой границе.

Порог найден перебором с точностью до копейки: `81 237.97` — наименьшая досрочка
на 3-м месяце, сокращающая срок до 11 месяцев. Остаток после платежа №3 при `E_3 = 0.01`
равен `761 080.27` против `761 080.28` без досрочки — разница ровно в копейку,
процентов это не экономит вовсе.

Отдельно стоит строка `81 237.96`: срок остаётся 12 месяцев, но **последний платёж
равен `0.01`**. Это законный результат по правилу 3.4 при сокращении срока (там условие
`k = n` не применяется, срок свободен), а не дефект. Тест, требующий «последний платёж
сопоставим с регулярным», упадёт здесь ложно.

> **Обязательный тест-кейс.** Копеечная досрочка: срок не меняется, экономия `0.00`,
> остаток сдвигается ровно на копейку, все инварианты держатся. Плюс граница
> `81 237.96 / 81 237.97` — переход 12 → 11 месяцев.

### 4.3. Форма строки графика

Строка содержит **шесть** полей. Тело и досрочка разделены: иначе эталонные таблицы 6.2
не сверить, И-1 (`Σ (D_k + E_k) = S`) не проверить, а фактически применённую сумму
досрочки (раздел 5, обрезка по остатку) нечем вернуть вызывающей стороне.

| Поле | Символ | Смысл |
|---|---|---|
| `номер` | `k` | Номер платёжного месяца, с 1 |
| `платёж` | `A_k` | Регулярный платёж месяца; в последней строке — балансирующий |
| `проценты` | `I_k` | Процентная часть |
| `тело` | `D_k` | Основная часть регулярного платежа, **без** досрочки |
| `досрочка` | `E_k` | Фактически применённая досрочка (уже обрезанная по остатку), `0.00` если её не было |
| `остаток` | `B_k` | Остаток основного долга после платежа и досрочки |

### 4.4. Исключение из И-3: график, закрытый досрочкой

И-3 требует, чтобы последний платёж был балансирующим. Это верно, пока долг закрывает
**платёж**. Если долг закрывает **досрочка**, последняя строка несёт обычный регулярный
платёж, а балансировка не срабатывает вовсе: правило 3.4 проверяется до внесения
досрочки, а на тот момент платёж остаток ещё не перекрывал.

Пример — досрочка ровно в остаток на третьем месяце кредита 6.1:

```
k=3  платёж 88 848.79 (регулярный)  проценты 8 415.14  тело 80 433.65
     досрочка 761 080.28            остаток 0.00
```

Здесь `money(B_2 + I_3) = 849 929.07`, а фактический платёж — `88 848.79`.
Формула И-3 к этой строке неприменима.

> **Точная редакция И-3.** Балансирующим обязан быть последний платёж графика,
> закрытого платежом. Для графика, закрытого досрочкой, требование иное:
> последний платёж равен регулярному `A`, а в ноль долг выводит поле `E_k`.
> Инвариант И-2 (остаток строго ноль) действует в обоих случаях без исключений.

Тест обязан различать эти два случая, а не применять формулу И-3 ко всем графикам
подряд: во втором случае она даёт ложное падение.

## 5. Поведение в вырожденных случаях

| Случай | Поведение | Проверено расчётом |
|---|---|---|
| **Ставка 0 %** | **Допустима.** Формула 3.2 вырождается; используется `A = money(S / n)`. Все `I_k = 0`, И-4 выполняется в форме «все проценты равны нулю», И-6 сохраняется (`D_k = A_k > 0`). | `120 000.00 / 0 % / 12 мес` → `A = 10 000.00`, 12 строк, проценты `0.00`, остаток `0.00` |
| **Отрицательная ставка** | Ошибка валидации `ValueError`, расчёт не выполняется. `r ≥ 0` — предусловие, наравне с `S_req > 0`. Отрицательная ставка вне области варианта B4: она ломает И-4 и И-7 и не встречается в потребительском кредите. | Не считается, отвергается на входе |
| **Срок 1 месяц** | Единственный платёж — он же последний и балансирующий: `A_1 = money(S + money(S·i))`, `D_1 = S`, `B_1 = 0`. | `100 000.00 / 12 % / 1 мес` → `A_1 = 101 000.00`, `I_1 = 1 000.00`, `D_1 = 100 000.00` |
| **Досрочка больше остатка** | Обрезается до остатка **после разнесения платежа**, по формуле раздела 3.6: `E_k_факт = min(E_k, B_k_до_досрочки)`. Излишек **не возвращается и не переносится** — калькулятор его не моделирует, а сигнализирует вызывающей стороне фактически применённой суммой. Кредит закрывается в этом же месяце. | При остатке `761 080.28` внесение `5 000 000.00` → применено `761 080.28`, график 3 строки, остаток `0.00` |
| **Досрочка ровно в остаток** | Кредит закрывается в этом же месяце, следующих строк нет. Граница с предыдущим случаем — та же ветка кода, но без обрезки. | Внесение ровно `761 080.28` → 3 строки, остаток `0.00` |
| **Платёж не покрывает проценты** | **Достижимо.** Ошибка `PaymentDoesNotAmortise`, график не строится. | См. 5.1 |
| **Отрицательная сумма** | Ошибка валидации `ValueError`, расчёт не выполняется. `S_req > 0` — предусловие. | Не считается, отвергается на входе |
| **Нулевая сумма** | Ошибка валидации `ValueError`. Пустой график **не** является допустимым результатом: `S = 0` — это не кредит, а отсутствие кредита, и молчаливый пустой график маскирует дефект вызывающего кода. | Не считается, отвергается на входе |

### 5.1. Случай «платёж не покрывает проценты» — обоснование

Аналитически при `i > 0` всегда `A > S·i`, поэтому кажется, что случай недостижим.
После округления до копеек это перестаёт быть верным. Прогон по 924 комбинациям
(`S` от `1.00` до `50 000 000.00`, `n` от 1 до 840, ставка от 0 % до 365 %) дал
**201 нарушение**, все — при `S = 1.00`.

Минимальная встреченная разница `A − I_1` равна ровно `0.00`; строго отрицательной
не встретилось ни разу. Значит отказ выглядит не как «долг растёт», а как
**`D_k = 0` и зацикливание**: остаток не уменьшается, график не заканчивается.

Воспроизведение: `S = 1.00`, ставка 12 %, `n = 120`.

```
A = 0.01
k=1  balance=1.00  interest=0.01  payment=0.01  principal=0.00   ← остаток не сдвинулся
```

Порог для этих параметров: наименьшее тело, которое ещё амортизируется, — `0.35`
(`A = 0.01`, `I_1 = 0.00`, `D_1 = 0.01`).

Требование к реализации: цикл построения графика **обязан** иметь защиту. Если
`D_k ≤ 0` при `B_{k−1} > 0` — поднимать `PaymentDoesNotAmortise`, а не крутиться.
Тест на незавершаемость обязателен и должен падать по счётчику итераций, а не по таймауту.

## 7. Как тесты используют этот документ

| Что проверяем | Источник ожидания |
|---|---|
| Точные суммы графиков | Таблицы 6.1–6.3, посимвольно |
| Инварианты | Раздел 4, применяются ко всем трём примерам и к генерируемым кейсам |
| Границы | Раздел 5, каждая строка таблицы — отдельный тест |
| Незацикливание | 5.1, счётчик итераций внутри построителя графика |
| Дисциплина округления | 1.1, статическая проверка по `calc/` |
| Форма строки графика | 4.3, шесть полей, тело и досрочка раздельно |

**Обязательные тест-кейсы из находок.** Три случая ниже найдены расчётом при подготовке
спеки, а не взяты из требований. Каждый ломает «очевидное» ожидание, поэтому вынесен
отдельно — их пропуск означает, что регресс проверяет не то, что происходит.

| № | Кейс | Что ломает | Раздел |
|---|---|---|---|
| Н-1 | Хвост `0.01` и фиктивный 13-й платёж при уменьшении платежа | Правило балансирующего платежа без условия `k = n` | 3.4, 6.2 |
| Н-2 | Совпадение соседних процентов (`0.01` пять месяцев подряд) | Строгое `I_k > I_{k+1}` | 4.1 |
| Н-3 | Копеечная досрочка не сокращает срок; на пороге `81 237.96` последний платёж равен `0.01` | Строгое `< n` и «последний платёж сопоставим с регулярным» | 4.2 |
| Н-4 | График, закрытый досрочкой, не имеет балансирующего платежа | Формула И-3, применённая ко всем графикам подряд | 4.4 |

> В таблицах 6.1 и 6.3 колонка «досрочка» опущена как пустая: во всех строках
> этих примеров `E_k = 0.00`. Форма строки от этого не меняется — полей всегда шесть.

## 8. Ограничения

Раздел честный и намеренно отдельный: ниже — то, что **сознательно не покрыто**.

### 8.1. Не реализовано по решению

| Что | Почему |
|---|---|
| Фактические дни, ACT/365, ACT/ACT | Выбрана база 30/360. Реальный банк считает по фактическим дням, и на 15 годах расхождение с 30/360 — заметная величина. Это осознанная замена реальной модели на упрощённую ради воспроизводимости тестов. |
| Високосный год | Следствие 30/360: февраль в модели равен 30 дням. Дефекты, связанные с 29 февраля, этот регресс **не поймает**. |
| Ежегодная страховка | Требует пересчёта премии от убывающего остатка и вставки платежей в график — отдельная механика, не влезающая в объём ДЗ. |
| Ежемесячная страховка | То же плюс влияние на сам аннуитет. |
| Скидка к ставке за страховку | Самая частая реальная схема и самый вероятный источник дефектов в проде. Не покрыта — это главный пробел регресса, и его стоит назвать вслух в отчёте. |
| Дифференцированные платежи | Область — аннуитет. |
| Комиссии, сборы, пени, просрочка | Вне варианта B4. |
| Частичная досрочка с переносом излишка | При досрочке больше остатка излишек просто обрезается (раздел 5). Реальный банк вернул бы его или зачёл — не моделируется. |
| Плавающая ставка, изменение ставки в течение срока | Ставка постоянна на всём сроке. |
| Отсрочка первого платежа, каникулы | Не моделируются. |
| Валюта, мультивалютность | Все суммы в одной валюте, признак валюты отсутствует. |

### 8.2. Известные слабые места самой спеки

- **Премия считается от `S_req`, а не от тела кредита.** Это выбрано, чтобы избежать
  круговой зависимости при схеме «в кредит». Часть банков считает от полного тела —
  тогда все числа примера 3b будут другими. Если требование изменится, пример 3b
  пересчитывается целиком.
- **Дата первого платежа не определена.** График в модели — это последовательность
  номеров месяцев, а не календарь. Любой дефект, связанный с календарём, вне охвата.
- **Порядок «досрочка после разнесения платежа» — решение спеки, а не универсальная
  истина.** Если реализация спишет `E_k` до начисления процентов, числа примера 2
  разойдутся уже на 4-м месяце. Тест на порядок обязателен.
- **Скан на неамортизируемость (5.1) не исчерпывающий**: 924 комбинации — сетка,
  а не полный перебор. Утверждение «строго отрицательной разницы не бывает»
  проверено на этой сетке и не доказано.
- **Порог `81 237.97` из 4.2 привязан к конкретному кредиту** (`1 000 000.00 / 12 % /
  12 мес`, досрочка на 3-м месяце). Это не универсальная константа: при других параметрах
  он другой. Тест обязан хранить и порог, и параметры, к которым тот относится.
- **Первая редакция спеки содержала два ложных инварианта** — строгое `I_k > I_{k+1}`
  (И-4) и строгое сокращение срока при любой досрочке (И-10). Оба обнаружены расчётом
  до написания кода и исправлены в этой редакции. Если бы тесты писались по первой
  редакции, они падали бы ложно на кейсах Н-2 и Н-3.
- **Отрицательная ставка закрыта запретом, а не моделью.** `r < 0` отвергается
  на входе (раздел 5). Это решение об области, а не утверждение, что такой кредит
  невозможен.
- **Вторая редакция спеки содержала невычисленное число.** В таблице 4.2 экономия
  для досрочки `1.00` стояла как `0.00`, тогда как расчёт даёт `0.09`. Ошибка
  ровно того сорта, против которого написан весь этот документ: строка таблицы
  заполнена по аналогии с соседней, а не посчитана. Найдена агентом, писавшим
  тесты на досрочку, и подтверждена независимым пересчётом. Урок в том, что
  «нулевое сокращение срока» и «нулевая экономия процентов» — разные условия.
- **Предусловие на тариф страхования `ρ` не задано.** Ни раздел 2, ни 3.5, ни 5
  не говорят, допустим ли отрицательный тариф и есть ли верхняя граница.
  Реализация отвергает `ρ < 0` по аналогии с И-7, но это вывод, а не буква спеки.
  Пробел открыт и ждёт решения.
- **Поведение досрочки на месяц, до которого график не дожил, не определено.**
  При сокращении срока крупной досрочкой более поздние ключи словаря просто
  не применяются. Ошибка это или штатное игнорирование — спека не говорит.
- **Масштаб агрегатов не оговорён.** И-8 сформулирован для величин графика;
  про `premium`, `paid_to_bank`, `out_of_pocket` не сказано ничего.

### 8.3. Что не проверялось вовсе

Производительность на длинных сроках, потокобезопасность, поведение при `n` больше
нескольких тысяч, локализация, сериализация графика, совместимость с внешними API.
